Cloud Metadata SSRF

HIGH SEVERITY Credential Access / Cloud Abuse Signature Pattern Matching 0 Detections Recorded
🛡️ Attack Overview

Server-Side Request Forgery targeting cloud metadata services enables attackers to coerce backend cloud applications into requesting internal link-local metadata endpoints (169.254.169.254) to steal temporary IAM security credentials.

⚙️ How It Works (Adversary Mechanics)

The attacker inputs the cloud metadata IP (169.254.169.254) into URL ingestion features (e.g. webhooks, file downloaders, image converters). The cloud instance queries the link-local metadata daemon and returns instance identity tokens.

🔄 Attack Progression Flow
Attacker ──[ GET /fetch?url=http://169.254.169.254/latest/meta-data/iam/security-credentials/ ]──> Cloud Server ──[ IDS Packet Inspection ]──> Cloud Metadata Signature Triggered ──[ Source IP Quarantined ]
🔬 Actual IDS Detection Implementation

SignatureDetector evaluates regex r'(?:169\.254\.169\.254|metadata\.google\.internal|latest/meta-data)' against all application payloads. Detects cloud token theft attempts immediately.

🚨 Impact & Defensive Mitigation
Security Impact:

Exfiltration of AWS / GCP / Azure IAM credentials, cloud account takeover, data breach, and infrastructure compromise.

Defensive Mitigation & Firewall Rule:

Enforce IMDSv2 (requiring PUT token header), disable link-local routing from container runtimes, implement strict URL whitelist parsing, and IDS firewall blocking.
