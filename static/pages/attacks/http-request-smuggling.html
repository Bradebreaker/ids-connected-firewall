HTTP Request Smuggling

HIGH SEVERITY Protocol Anomaly / Desync (CWE-444) Protocol Anomaly & Signature Matching 0 Detections Recorded
🛡️ Attack Overview

HTTP Request Smuggling exploits discrepancies between frontend reverse proxies and backend web servers in parsing ambiguous HTTP headers (Content-Length and Transfer-Encoding), enabling attackers to smuggle unauthorized requests into other users' HTTP streams.

⚙️ How It Works (Adversary Mechanics)

The attacker sends a crafted request containing conflicting headers: both Transfer-Encoding: chunked and Content-Length. Depending on whether the frontend or backend prioritizes Transfer-Encoding (CL.TE or TE.CL), one server reads fewer bytes, leaving the remainder in the TCP buffer to prepend to the next user's request.

🔄 Attack Progression Flow
Attacker ──[ Dual CL & TE Headers ]──> Frontend Reverse Proxy ──[ Different Framing Priority ]──> Smuggled Payload Prefixed to Next User Request ──[ IDS Protocol Anomaly Detected ]
🔬 Actual IDS Detection Implementation

SignatureDetector inspects the HTTP header stream for dual Content-Length and Transfer-Encoding header combinations or obfuscated Transfer-Encoding variants using regex r'(?i)(?:transfer-encoding\s*:[^\r\n]*chunked.*content-length|content-length\s*:[^\r\n]*\d+.*transfer-encoding)'.

🚨 Impact & Defensive Mitigation
Security Impact:

Cache poisoning, credential hijacking, session hijacking, security control bypass, and internal API abuse.

Defensive Mitigation & Firewall Rule:

Disable HTTP connection reuse for backend connections, standardize on HTTP/2 end-to-end, reject ambiguous request headers at frontend proxies, and enforce IDS firewall rules.
